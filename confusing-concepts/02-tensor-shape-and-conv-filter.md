# 텐서 shape와 이미지, 그리고 conv 필터가 곱해지는 방식

## 헷갈렸던 점

> PyTorch에서 shape가 유독 어렵다. 텐서 자체도 잘 와닿지 않고, 차원을 이미지로 떠올리기가 어렵다.
> "3 × 3 × 채널"이라는 말도 와닿지 않는다.
> RGB 이미지는 R에 해당하는 2차원 표, G 표, B 표가 있고 그 3장을 합치면 28 × 28 × 3인 건가?
> 그러면 각 픽셀 위치에서 (r, g, b)로 색이 표현되는 건가? 그런데 이걸 CNN에서 쓰니 너무 복잡하다.

## 결론

- **텐서 = 숫자를 몇 방향으로 늘어놓았는지**를 나타낸 상자. shape는 바깥에서부터 몇 개씩 들어 있는지를 적은 것뿐이다.
- **RGB 이해는 정확하다.** R, G, B 표 3장을 겹친 것이 컬러 이미지이고, 같은 위치의 숫자 3개가 그 픽셀의 `(r, g, b)`다. PyTorch는 장 수를 먼저 적어서 `(3, 28, 28)`로 쓴다.
- **채널(C) = 표가 몇 장인지.** 입력에서는 색(R, G, B)이지만, conv를 지나고 나면 "필터가 찾은 무늬 지도가 몇 장인지"가 된다.
- **필터 하나는 입력의 모든 장을 한 번에 덮고, 숫자 하나를 만든다.** 그래서 필터 크기가 `3 × 3 × (입력 장 수)`이고, 필터 1개 = 출력 표 1장이다.

## 1. 텐서: 0차원부터 4차원까지

```
0차원  숫자 하나           5                         shape ()
1차원  한 줄               [5, 2, 7]                 shape (3,)
2차원  표                  [[5, 2, 7],               shape (2, 3)     2줄 × 3칸
                            [1, 0, 4]]
3차원  표 여러 장          표 (2, 3)을 3장 겹침      shape (3, 2, 3)
4차원  그 묶음 여러 개     위 묶음이 128개           shape (128, 3, 2, 3)
```

그림으로 보면:

```
0차원: 점          1차원: 줄          2차원: 표          3차원: 표를 겹친 것

   5              [5 2 7]           ┌───────┐              ┌───────┐
                                    │ 5 2 7 │            ┌───────┐ │
                                    │ 1 0 4 │          ┌───────┐ │ │
                                    └───────┘          │ 5 2 7 │ │─┘
                                                       │ 1 0 4 │─┘
                                                       └───────┘
                                                        표 3장

4차원: 3차원 덩어리를 여러 개 나란히 놓은 것

   [표 3장]  [표 3장]  [표 3장]  ...  [표 3장]
    1번째     2번째     3번째          128번째
```

lab01에서 실제로 나온 텐서들:

| 텐서 | shape | 차원 | 뜻 |
|---|---|---|---|
| `loss` | `()` | 0 | 틀린 정도, 숫자 하나 |
| `y` | `(128,)` | 1 | 정답 숫자 128개 |
| `logits` | `(128, 10)` | 2 | 이미지 128장 × 숫자 0~9 점수 10개 |
| 이미지 한 장 | `(1, 28, 28)` | 3 | 흑백 표 1장 |
| `x` | `(128, 1, 28, 28)` | 4 | 이미지 128장 묶음 |

## 2. 이미지를 텐서로: 흑백과 컬러

### 흑백 = 표 한 장

픽셀마다 밝기 숫자 하나 (`0` = 검정, `1` = 흰색). `ToTensor()`가 원래의 0~255를 0~1로 바꿔 준다.

```
0.0  0.0  0.9  0.0
0.0  0.9  0.9  0.0
0.0  0.0  0.9  0.0      <- 숫자 "1" 모양
0.0  0.0  0.9  0.0
```

MNIST는 이게 28 × 28이다. 형식을 컬러와 맞추려고 "표 1장"이라고 적어서 shape는 `(1, 28, 28)`.

### 컬러 = 표 3장

```
   R 표 (28×28)      G 표 (28×28)      B 표 (28×28)
  ┌───────────┐     ┌───────────┐     ┌───────────┐
  │ 빨강 세기  │     │ 초록 세기  │     │ 파랑 세기  │
  │  ...      │     │  ...      │     │  ...      │
  └───────────┘     └───────────┘     └───────────┘

  (5번째 줄, 7번째 칸) 픽셀의 색 = (R표[5][7], G표[5][7], B표[5][7])
```

- `28 × 28 × 3`과 `(3, 28, 28)`은 **같은 데이터**다. 적는 순서만 다르다.
  - PyTorch: `(C, H, W)` → 장 수를 먼저
  - numpy / matplotlib / TensorFlow: `(H, W, C)` → 장 수를 나중에
- 그래서 PyTorch 텐서를 `plt.imshow`로 볼 때는 `x.permute(1, 2, 0)`으로 축 순서를 바꿔야 한다. (`reshape`를 쓰면 shape는 맞아도 픽셀이 뒤섞여 이미지가 깨진다.)

### batch = 이미지 여러 장

이미지 128장을 묶으면 맨 앞에 개수가 붙는다: `(128, 3, 28, 28)` = `(B, C, H, W)`

- `B` (batch): 이미지 몇 장
- `C` (channel): 표가 몇 장 (흑백 1, 컬러 3, conv 뒤에는 필터 개수)
- `H`, `W`: 세로, 가로 픽셀 수

## 3. conv 필터: 흑백 이미지부터

**필터 = 3 × 3짜리 작은 숫자 표.** 이 9개 숫자가 학습되는 weight다.

필터를 이미지의 한 부분에 올려놓고, **겹친 칸끼리 곱해서 전부 더한다.**

```
이미지의 3×3 부분      필터
 0.0  0.9  0.0        -1  2  -1
 0.0  0.9  0.0    ×   -1  2  -1    =  (0×-1)+(0.9×2)+(0×-1)
 0.0  0.9  0.0        -1  2  -1       +(0×-1)+(0.9×2)+(0×-1)
                                      +(0×-1)+(0.9×2)+(0×-1)  =  5.4  (숫자 하나)
```

- **곱셈 9번 → 더해서 숫자 1개** (실제로는 여기에 bias `b`를 하나 더 더한다)
- 이 필터는 가운데 세로줄이 밝을수록 큰 값이 나오므로 "세로선 탐지기"다.

필터를 한 칸씩 옆으로, 아래로 옮기며 이미지 전체를 훑으면 위치마다 숫자가 하나씩 나오고, 그게 모여 **새 표 한 장(feature map)**이 된다. "어디에 세로선이 있는지 표시한 지도"다.

```
입력 (28×28)                          출력 (28×28)
┌──────────────┐                      ┌──────────────┐
│┌───┐         │   필터를 한 칸씩     │■             │
││3×3│ → → →   │   옮기며 곱하고 더함 │  (위치마다    │
│└───┘         │  ─────────────────▶  │   숫자 1개)  │
│  ↓           │                      │              │
└──────────────┘                      └──────────────┘
```

`padding=1`은 테두리에 0을 한 줄 둘러서, 가장자리에서도 3×3 창을 올릴 수 있게 해 준다. 그래서 출력도 28 × 28로 유지된다. (padding이 없으면 26 × 26으로 줄어든다.)

## 4. 컬러 이미지 `(3, 28, 28)`에서 필터: "3 × 3 × 채널"의 뜻

입력이 표 3장이면 **필터도 3장짜리**가 된다. 3 × 3 창이 R, G, B 세 장을 한꺼번에 뚫고 본다.

```
R 표의 3×3 부분  ×  필터의 1번째 장 (3×3)   → 곱셈 9번  ┐
G 표의 3×3 부분  ×  필터의 2번째 장 (3×3)   → 곱셈 9번  ├─ 27개를 전부 더함 (+ bias) = 숫자 하나
B 표의 3×3 부분  ×  필터의 3번째 장 (3×3)   → 곱셈 9번  ┘
```

- 필터 하나의 크기 = `3 × 3 × 3` = weight 27개
- 한 위치에서 **곱셈 27번 → 숫자 1개**
- 필터가 여전히 **숫자 1개만** 만드는 이유: R, G, B 결과를 따로 두지 않고 전부 더해 버리기 때문

두 가지 규칙:

1. **필터의 장 수 = 입력의 장 수.** 직접 정하는 게 아니라 입력에 맞춰 자동으로 정해진다.
2. **필터 1개 → 출력 표 1장.** 입력이 몇 장이든 상관없다.

## 5. 필터를 여러 개 쓰면 = 출력 채널

필터 하나는 무늬 하나만 찾으니, 서로 다른 필터를 여러 개 쓴다. 필터마다 표 한 장씩 나온다.

```
입력: 표 3장 (R, G, B)  →  필터 32개  →  출력: 표 32장
                                          (세로선 지도, 가로선 지도, 모서리 지도, ...)
```

이게 `nn.Conv2d(3, 32, 3)`의 뜻이다: **입력 3장, 필터 32개, 창 크기 3 × 3**.

- 여기서부터 채널은 **색이 아니라 "무늬 지도가 몇 장인지"**다.
- 다음 층 `nn.Conv2d(32, 64, 3)`: 입력이 32장이니 필터 하나가 `3 × 3 × 32`, 그런 필터가 64개 → 출력 64장.

weight shape로 확인하면:

```python
conv = nn.Conv2d(3, 32, 3, padding=1)
print(conv.weight.shape)   # (32, 3, 3, 3) = (필터 개수, 입력 장 수, 3, 3)
print(conv.bias.shape)     # (32,)         = 필터마다 bias 1개
```

## 6. 곱셈이 몇 번 일어나는가

`Conv2d(3, 32, 3, padding=1)`에 `(3, 28, 28)` 이미지 한 장을 넣으면:

| 단계 | 계산 | 곱셈 수 |
|---|---|---|
| 필터 1개, 위치 1곳 | `3 × 3 × 3` | 27 |
| 필터 1개, 이미지 전체 | 위치 `28 × 28 = 784`곳 × 27 | 21,168 |
| 필터 32개 | 21,168 × 32 | 677,376 |

- 출력: `(32, 28, 28)` → 표 32장, 각각 28 × 28
- weight 개수: `32 × 3 × 3 × 3 + 32(bias) = 896`개
- 곱셈은 67만 번이지만 weight는 896개뿐이다. **같은 필터를 모든 위치에서 재사용**하기 때문. 이게 CNN이 Dense보다 weight가 훨씬 적은 이유다.

lab01 모델(흑백 MNIST)을 이미지 한 장 기준으로 세면:

| 층 | 입력 → 출력 | 위치 1곳당 곱셈 | 위치 수 | 필터 수 | 총 곱셈 | weight 수 |
|---|---|---|---|---|---|---|
| `Conv2d(1, 32, 3)` | `(1,28,28)` → `(32,28,28)` | `3×3×1 = 9` | 784 | 32 | 225,792 | 320 |
| `MaxPool2d(2)` | → `(32,14,14)` | 곱셈 없음 (최댓값 고르기) | | | | 0 |
| `Conv2d(32, 64, 3)` | `(32,14,14)` → `(64,14,14)` | `3×3×32 = 288` | 196 | 64 | 3,612,672 | 18,496 |
| `MaxPool2d(2)` | → `(64,7,7)` | | | | | 0 |
| `Flatten` | → `(3136,)` | 곱셈 없음 (한 줄로 펴기) | | | | 0 |
| `Linear(3136, 10)` | → `(10,)` | | | | 31,360 | 31,370 |

- weight 수 = `필터 수 × (3 × 3 × 입력 장 수) + 필터 수(bias)`
  - 예: `64 × 288 + 64 = 18,496`
- 두 번째 conv가 곱셈이 가장 많다. 입력 장 수(32)가 커서 위치 1곳당 곱셈이 288번이기 때문.

## 7. Conv1d / Conv2d / Conv3d

숫자는 **필터가 몇 방향으로 움직이는지**다. 하는 일(겹친 칸끼리 곱해서 더하기)은 같다.

| | 필터가 움직이는 방향 | 입력 shape | 필터 1개 크기 | 쓰는 곳 |
|---|---|---|---|---|
| `Conv1d` | 1방향 (좌우) | `(B, C, L)` | `3 × C` | 소리, 센서, 시계열 |
| `Conv2d` | 2방향 (상하, 좌우) | `(B, C, H, W)` | `3 × 3 × C` | 이미지 |
| `Conv3d` | 3방향 (상하, 좌우, 앞뒤) | `(B, C, D, H, W)` | `3 × 3 × 3 × C` | 영상(시간 축), CT/MRI(깊이 축) |

**컬러 이미지는 축이 3개(C, H, W)인데 왜 Conv3d가 아니라 Conv2d인가?**
필터가 채널 방향으로는 움직이지 않기 때문이다. R, G, B 세 장을 한 번에 다 덮은 채로 상하, 좌우로만 움직인다. 움직이는 방향이 2개라서 2d다.

## 기억할 것

- 텐서 shape는 "바깥에서부터 몇 개씩"이다. `(128, 3, 28, 28)` = 이미지 128장, 각각 표 3장, 각 표는 28 × 28.
- 필터 하나 = `3 × 3 × (입력 장 수)`. 한 위치에서 그만큼 곱하고 전부 더해 **숫자 1개**.
- 필터 개수 = 출력 장 수. `Conv2d(in, out, k)`의 `in`은 입력 장 수, `out`은 필터 개수.
- B(batch)는 모델을 지나도 절대 안 바뀐다. 바뀌면 버그.
- shape가 헷갈리면 층마다 출력해 본다:

```python
h = x.to(device)
for layer in model:
    h = layer(h)
    print(f"{layer.__class__.__name__:10s} {tuple(h.shape)}")
```
